# 三阶段围捕测试模式

ZooidManager 当前测试模式直接通过 USB 接收器控制一台目标车和三台追捕车，
不需要启动 ROS、Webots、Python、强化学习或 Voronoi 模块。

## 启动条件

- 接收器已连接并持续收到机器人状态反馈。
- 至少四台机器人在线、已激活，且最近 250 ms 内有有效反馈。
- 实验场地已清空无关物体，操作员可以随时点击“停止测试”。

点击“开始测试”后，系统按当前真实硬件 ID 从小到大排序：最小 ID 是目标
车，后面三个 ID 是追捕车。多余机器人不参加任务并持续收到零速指令。角色映
射在本轮任务中保持不变；重新开始时才重新扫描和分配。

## 任务阶段

1. `PURSUIT`：追捕车靠近目标周围约 0.31 m 的外环，目标车低速逃逸。
2. `SURROUND`：三台追捕车形成半径约 0.24 m、间隔 120° 的包围环。
3. `CAPTURE`：包围槽位收缩到约 0.1224 m，连续满足距离和角度条件后完成。
4. `CAPTURED`：任务终态，目标车和三台追捕车全部停车。

队形破坏时，状态机会自动从 CAPTURE 退回 SURROUND/PURSUIT，或从
SURROUND 退回 PURSUIT。界面显示当前阶段、真实角色 ID、三台追捕车到目标
的距离和捕获稳定进度。

目标进入靠墙或角落、无法完整放下 0.24 m 三角环的区域时，会先驶向场地中心
恢复到可包围区域；后续逃逸候选也必须能容纳完整三角环。SURROUND 阶段允许
过近的追捕车向外恢复到 0.24 m 名义半径，避免旧版“只准收缩”造成永久卡住。

## 串口速度命令

控制器按标准 e-puck2 的 41 mm 轮径、53 mm 轮距和每圈 1000 电机步进行换算：
`1000 / (π × 0.041) ≈ 7764 steps/m`。旧版误用了 `1000`，使直行和转向
都只有声明速度的约 12.9%。修复后仍限制变化率并饱和到 `[-1000, 1000]`，
随后调用现有 `controlRobotSpeed(realId, left, right, color)`，使用
`controlMode = 1` 和既有 `+2007` 编码写入 USB 接收器帧。

追捕车在 PURSUIT、SURROUND、CAPTURE 三个阶段分别不超过 0.100、0.085、
0.070 m/s，理论直行命令约 776、660、543；目标车常规上限分别为 0.040、
0.035、0.025 m/s，理论约为 311、272、194。转弯时左右轮差速可能更高，但仍受
`±1000` 硬限幅保护。追捕者之间采用连续分离与切向绕行，不再在 0.14 m 处
把双方前进速度直接清零；跨越目标另一侧槽位时先绕目标调角度，再径向收缩。
所有车辆在朝场外行驶且进入边界前 0.03 m 时会按剩余距离渐进降低平移速度，
同时保留转向指令，使车辆先转回场内而不是继续顶墙。
由于仓库不含当前接收器/机器人端固件，`+2007` 解码是否严格等于 steps/s 仍需
通过架空轮转数或短直线距离做一次实机标定。

几何和速度参数集中在 `manager/ZooidPursuitProfile.h`，轮径、轮距与步数换算
集中在 `manager/ZooidPursuitControl.h` 的 `PursuitDriveCalibration`。后续实车
调参应修改这些 SI 单位参数，不要再次通过错误的轮速比例放大常数。

状态机只在四台参与车都各自收到新反馈后推进；重复发送同一帧不会虚增阶段计
时或继续抬高平滑轮速。反馈停更 100 ms 会先发送零速，达到 250 ms 后结束任务
并报告故障。目标速度按反馈时间戳估计并低通，避免 60 Hz 控制周期把相机跳变
放大；量化脉冲先限制到 0.12 m/s，再进行 0.20 s 低通，避免把正常的离散位移
误判为零速度。接收坐标轴的方向仍保持现车协议原样，需在架空轮四航向测试中单独确认，
未经实测不改全局坐标约定。

## 安全停止

以下任一情况都会清除相关发送队列并连续三轮发送零速：

- 点击“停止测试”；
- 任一参与机器人掉线、停用或反馈达到 250 ms；
- 位姿或控制计算出现非有限数值；
- 接收器报告写入失败；
- 捕获完成或应用退出。

停止操作可重复执行。发生故障后先现场确认所有机器人已经停止，再排查接收器、
定位反馈和机器人电源。

## 构建与核心测试

核心逻辑不依赖 Qt，可使用 MinGW 直接构建 `tests/zooid_core_tests.cpp`。完整
应用通过 Qt 5.9.7 qmake 和 MinGW 5.3 构建；一键构建命令为：

```powershell
.\scripts\build_windows.ps1 -Configuration Release
```

部署程序位于 `.build-windows-deploy/release/ZooidManager.exe`。核心回归除静态
几何外，还从真实场地尺寸 `1.46 × 0.914 m` 的墙边布局和 10 cm 聚集布局逐步
积分左右轮命令，要求在 30 秒内实际经过 PURSUIT、SURROUND、CAPTURE 并到达
CAPTURED。
